## 1. 项目概览

### 1.1 主要结果

| 项目                | 结果                                                                     |
| ----------------- | ---------------------------------------------------------------------- |
| 交付配置              | `lr = 2e-5` · `batch_size = 16` · `dropout = 0.1` · `max_length = 128` |
| **Test Accuracy** | **83.08% ± 0.28%**（3 seeds: 42 / 66 / 99）                              |
| **Test Macro-F1** | **81.98% ± 0.15%**                                                     |
| 训练成本              | 单 seed 约 2–4 min，全量约 1 h（RTX 3070 Ti Laptop, 8 GB）                     |
| 记录方式              | SwanLab 全程记录，`swanlog/` 下 21 个 run 可离线解析                               |

### 1.2 主要工作

- **单变量消融**：Dropout（0.1 / 0.2 / 0.3 / 0.4）→ 学习率（1e-5 / 2e-5 / 3e-5）→ Batch Size（8 / 16），每次只动一个参数，其余锁定。
- **多种子重复**：每组 3 个种子，报告 `mean ± std` 当两组指标差距很小、在种子随机波动范围内，认为性能近似等价。
- **数据审计**：训练前统计三份数据的重复标题、标签冲突与长尾分布，并估计其对指标的影响。
- **可复现**：固定数据文件、固定 seeds、`cudnn.deterministic=True`，超参写入 `configs/params.json`，单条命令完成 3 个种子的训练。

## 2. 数据集

### 2.1 基本情况

来源为今日头条文本分类数据集（TNEWS）切片。每行 5 个字段、以 `_!_` 分隔，第 2 字段为类别 `code`，第 4 字段为新闻标题。**模型只使用标题**，共 15 个类别（标签 `100–116`，实际缺少 `105`、`111`）。

| 划分  | 文件             |  样本数 |
| --- | -------------- | ---: |
| 训练集 | `train_3k.txt` | 3000 |
| 验证集 | `dev_1k.txt`   | 1000 |
| 测试集 | `test_1k.txt`  | 1064 |

### 2.2 数据审计

对三份数据做标题级比对：

| 检查项               | 数量 | 影响                          |
| ----------------- | -: | --------------------------- |
| train 与 test 重复标题 | 31 | 约 2.9% 的测试样本在训练中出现过，指标略微偏乐观 |
| train 与 dev 重复标题  | 28 | 早停与选 checkpoint 的验证信号略偏乐观   |
| dev 与 test 重复标题   | 18 | 选参与评估共享样本，削弱独立性             |
| train 内部重复标题      | 63 | 等效训练样本量低于 3000              |
| 同名不同标签（跨划分冲突）     |  3 | 标注噪声，模型无法全部判对               |

本实验未修改原始数据，上述重叠会使指标偏高。

## 3. 方法

### 3.1 模型

```python
pooled = BertModel.from_pretrained("bert-base-chinese")(...).pooler_output   # [B, 768]
logits = Linear(768, 15)(Dropout(p)(pooled))                                # [B, 15]
loss   = CrossEntropyLoss(logits, labels)
```

- 取 **`pooler_output`**（`[CLS]` 经 `Linear + Tanh` 后的句子级向量），而非对所有 token 做 mean pooling。标题短、关键信息集中，`[CLS]` 在预训练阶段已被训练为聚合句义；实现上也不必处理 padding mask 的加权平均。
- 分类头只有一层线性层。3000 条样本难以支撑更深的头部，增加层数会加快过拟合。

### 3.2 训练配方

| 组件         | 设置                                 | 说明                                  |
| ---------- | ---------------------------------- | ----------------------------------- |
| 优化器        | AdamW（`weight_decay = 0`）          | 代码仅设置学习率，未启用权重衰减；本实验的正则项只来自 dropout |
| 学习率调度      | Linear warmup (10%) + linear decay | 前 188 步线性升温，避免初期大梯度破坏预训练权重          |
| 梯度裁剪       | `max_norm = 1.0`                   | 只缩放范数、不改变方向，抑制梯度爆炸                  |
| Batch size | 16                                 | 8 GB 显存上实测稳定；bs=32 未测（显存不足）         |
| 最大轮数       | 10                                 | 配合早停，21 次运行平均 8.2 轮（5–10 轮）         |
| 早停         | `patience = 3`                     | 监控 dev Acc，连续 3 轮未提升即停止             |
| 模型选择       | dev Acc 最高的 checkpoint             | 测试集不参与 run 内的 checkpoint 选择         |
| 随机种子       | 42 / 66 / 99                       | 覆盖 3 次独立初始化与数据打乱                    |

## 4. 实验设计

### 4.1 研究问题

| 编号  | 问题                        | 对应实验 |
| --- | ------------------------- | ---- |
| RQ1 | Dropout 如何影响过拟合边界与长尾类表现？  | G1   |
| RQ2 | 学习率如何影响收敛速度与训练稳定性？        | G2   |
| RQ3 | Batch size 如何影响梯度噪声与最终精度？ | G3   |

### 4.2 固定参数

```json
{
  "model_name": "bert-base-chinese",
  "max_length": 128,
  "max_epochs": 10,
  "patience": 3,
  "seed_list": [42, 66, 99],
  "max_norm": 1.0,
  "warmup_ratio": 0.1
}
```

### 4.3 实验矩阵：坐标下降而非全网格

| 组  | 维度         | 取值                | 锚点                |   runs |
| -- | ---------- | ----------------- | ----------------- | -----: |
| G0 | 初始基线       | `2e-5 / 16 / 0.2` | —                 |      3 |
| G1 | Dropout    | `0.1 / 0.3 / 0.4` | `2e-5 / 16 / 0.2` |      9 |
| G2 | 学习率        | `1e-5 / 3e-5`     | `2e-5 / 16 / 0.1` |      6 |
| G3 | Batch size | `8`               | `2e-5 / 16 / 0.1` |      3 |
|    |            |                   | **合计**            | **21** |

先固定 `lr=2e-5, bs=16` 扫 dropout（G1），确定 0.1 为最优后，再以 `2e-5 / 16 / 0.1` 为锚点扫学习率（G2）与 batch size（G3）。

两个未纳入的点：

- **`bs=32`**：未实测。按显存估算 OOM 风险较高（`max_length=128` 下 batch 翻倍、激活显存翻倍）；强行缩短序列又会引入「截断长度」这一额外变量。若需更大 batch，可用梯度累积（bs=16 × 累积 2 步）模拟。
- **`lr=5e-5`**：3e-5 已出现明显震荡，继续加大只会放大不稳定。

### 4.4 评估协议

| 阶段                     | 使用数据             | 决策依据            |
| ---------------------- | ---------------- | --------------- |
| run 内训练                | train            | —               |
| run 内早停 / 选 checkpoint | dev Acc          | 每个 run 独立保存最优权重 |
| 跨配置排序                  | test（3 seeds 均值） | 验收指标为 test Acc  |

每个 run 内部用 dev 做早停与模型选择，跨配置比较使用 3 个种子的 test 均值。dev 仅 1000 条，7 组配置的 dev 均值集中在 0.66 pp 的区间内，与种子噪声同量级，不足以区分组间差异。test 指标在训练结束后单独评估，由 `main.py` 汇总打印；SwanLab 只记录 dev 曲线与训练损失。

>表注：单标签多分类任务下，Micro-Precision、Micro-Recall、Micro-F1在数学上等价于对应数据集准确率Acc，因此每列仅展示一组 mean ± std；所有指标均为3个随机种子（42,66,99）独立实验取平均，单位为%。所有Micro指标均基于最优验证权重在对应数据集上评估得到。

Micro指标与Macro指标形成互补：Micro-Precision、Micro-Recall、Micro-F1在单标签多分类任务中，在数学上等价于对应数据集上的准确率Acc，反映模型在全部样本上的全局预测正确率，计算时不按类别加权，结果不会被长尾稀有类拉低；而Macro-F1对每一个类别平等加权计算，能够体现模型在稀有类别上的分类效果，二者形成评估上的互补关系。对比同一最优权重下的Dev Micro与Test Micro，能够直观观察模型全局层面的泛化落差，该指标不受宏平均指标对稀有类别敏感的特性干扰。

从验证集Micro指标来看，不同超参数下模型在验证集上的全局拟合上限差距较小；而测试集Micro指标的组间差异更大，说明超参数选择主要影响模型的泛化稳定性，而非单纯验证集拟合能力。较大学习率对应的实验组，指标标准差明显更高，说明学习率偏大时，随机初始化会对最终效果带来强烈扰动，模型稳定性变差；小批次训练的梯度噪声更高，虽然验证集指标稳定，但容易在验证集上命中局部最优，泛化能力存在波动。

Micro指标仅反映全局正确率，无法体现类别均衡性。部分实验组Micro指标表现尚可，但Macro-F1标准差偏高，代表模型仅在样本量大的优势类别上保持较好识别效果，长尾稀有类判别不稳定。因此本实验在超参数优选时，优先采用Macro-F1及其标准差作为核心评价依据，仅依靠准确率（Micro-F1）无法捕捉长尾分布带来的隐性性能退化。

> 表中单位均为 %；P / R / F1 为 macro 平均。ΔAcc 为 Test Acc 与 Dev Acc 之差，ΔF1 为 Test Macro-F1 与 Dev Macro-F1 之差，两列均由表中两位小数的均值直接相减。Dev 各列为 3 个种子在各自最优轮（dev Acc 最高）上的 `mean ± std`，Test 为加载该轮权重后在测试集上的结果。

从 Acc 口径来看：7 组中有 6 组的 Test Acc 低于 Dev Acc，平均落差为 −0.36 pp；仅配置 2 的 Test Acc 略高于 Dev Acc（+0.12 pp）。其中落差最大的两组是 lr=3e-5（−1.20 pp）与 bs=8（−0.57 pp），恰好也是种子间指标标准差最大的两组。这符合早停机制带来的规律：checkpoint 基于验证集 Acc 筛选，验证集 Acc 天然存在乐观偏差；尤其是 bs=8 这一组，验证集 Acc 在全部配置里最高（83.53%），但测试集 Acc 明显回落至 82.96%，该泛化落差也可以在 SwanLab 训练曲线上定位到对应的最优轮次。

从 Macro-F1 口径来看，正负方向并不统一：配置 1、3、4、5 的 ΔF1 为小幅正值，也就是测试集 Macro-F1 略高于验证集；配置 2、6、7 为负值，7 组平均 ΔF1 = −0.26 pp。Test Macro-F1 高于 Dev Macro-F1 容易被视作反常现象，这里从三点解释：

1. 差值幅度很小，属于抽样随机波动。测试集共 1064 条样本，单条样本对应约 0.094 pp，本组最大正向差值 +0.21 pp 仅等价于 2 条样本预测结果发生变化，该量级无法和数据集抽样噪声区分开。
2. 早停监控目标是 Dev Acc，不是 Dev Macro-F1。我们挑选权重时只优化、筛选 Acc，没有对 Dev Macro-F1 做择优。“测试集指标一定低于验证集”这个预期，只适用于作为筛选依据的 Acc；Dev Macro-F1 不参与 checkpoint 选择，因此不存在系统性高于测试集 Macro-F1 的必然性。
3. Acc 和 Macro-F1 在验证、测试集上的差距本身不一致。Acc 和 Macro-F1 之间存在固有 gap：验证集上 Acc − Macro-F1 差值区间为 1.20–3.21 pp，测试集上为 1.10–2.65 pp，验证集的 Acc-F1 间隙整体略宽。ΔF1 和 ΔAcc 不是独立的两个信号，二者满足恒等关系：

ΔF1 = ΔAcc + [(Dev Acc − Dev F1) − (Test Acc − Test F1)]

综合来看，验证集与测试集指标落差整体控制在 1.2 pp 以内，没有出现严重过拟合验证集的证据。其中配置 6、7 的指标衰减幅度显著更大，同时伴随很高的种子间波动，属于真实的泛化性能退化；而配置 1、3、4、5 的正向 ΔF1 仅为抽样噪声，不能理解为测试集分类难度低于验证集。

- 0.1 与 0.2 的性能差异主要体现在 Macro-F1 指标上：二者准确率 Acc 仅相差 0.03 pp（约对应 0.3 条样本），Macro-F1 相差 0.48 pp，F1 标准差相差 1.6 倍。在 Acc 基本等价的条件下，dropout=0.1 的 F1 更高、实验稳定性更强。随着 dropout 继续增大，指标下降不再对称。从 0.1 提升至 0.4，Acc 下降 0.50 pp，Macro-F1 下降 2.05 pp；F1 标准差由 0.15 扩大至 2.14，其中 dropout=0.3 组标准差达到 2.33，约为 0.1 组的 15.5 倍。该现象符合典型特征：模型对样本充足的多数类识别效果尚可，长尾稀有类率先出现性能失效。

- 两组离群实验结果可以佐证上述机制：
  - dp=0.3，seed=99：最优轮次 Acc 为 82.50%，Macro-F1 仅 76.54%，二者差距 5.96 pp；
  - dp=0.4，seed=42：Acc 为 83.00%，Macro-F1 仅 76.40%。
  两组模型准确率均处于正常区间，但 Macro-F1 显著下跌。按15分类的宏平均规则折算，5.96 pp 的差距等价于所有类别合计损失约89个F1百分点；如果性能损失集中在3个稀有类别上，平均每类F1下降约30个百分点（例如从0.6降至0.3），这和数据集里类别114仅14条验证样本的长尾分布情况吻合。

- 进一步提高 dropout 无法带来泛化性能提升：dropout=0.4 的末轮训练损失（0.071）是 dropout=0.1（0.029）的2.4倍，最优早停轮次也从6.7轮提前至4.0轮。但该现象不能直接判定为欠拟合：dropout 本身会抬高训练损失基线；dropout=0.4 的末轮验证损失（0.909）反而是四组里最低，验证集 Acc（83.10%）和 dropout=0.1（83.17%）基本持平。性能退化集中体现在 Macro-F1（79.93）与种子间标准差（2.14）上，说明强 Dropout 抑制的是稀有类的判别特征，而不是模型整体的拟合能力。综合指标变化可以判断：强 Dropout 并没有削弱模型对高频大类的拟合能力，而是破坏了稀有类微弱的特征表示，最终表现为 Macro-F1 大幅下降、不同种子之间结果剧烈震荡。

 结论：dropout = 0.1。在 Acc 持平的前提下，该取值可以获得更高的 Macro-F1，同时种子间实验波动更小。

图 4：同一组 run 的 Macro-F1 与三个 micro 指标。micro-P / micro-R / micro-F1 与图 3 的 dev Acc 完全重合，这是单标签多分类下的恒等式；Macro-F1 在第 1 轮比 Acc 低 6.8–11.0 pp，收敛后仍低 1.2–1.8 pp，差距来自长尾类。

- 学习率主要决定收敛速度与过拟合起始时机，对模型精度上限的影响有限。三组实验首轮验证集Acc差距可达6.0 pp，但最终性能最高点仅相差1.1 pp。首轮dev Acc均值为73.3 / 78.9 / 79.3（seed 42单独为74.7 / 80.0 / 80.9），三条曲线最优峰值依次为83.1 / 83.2 / 82.1。1e-5仅将进入82%区间的时间从第2轮延后至第3轮（81.3 → 82.4），并非无法达到该精度。
- 验证损失的谷底可以比Acc更早反映训练状态。三组损失谷底（3种子均值）分别出现在第3.7 / 3.0 / 2.7轮，之后以0.032 / 0.047 / 0.061每轮的斜率回升，末轮dev loss为0.800 / 0.949 / 0.993。学习率越大，损失谷底出现越早、回升斜率越陡峭，对应图中上排右侧损失曲线的分叉现象。
- 3e-5的核心缺陷是实验稳定性差。三个种子的最优轮次分散在第2 / 5 / 8轮，dev Acc波动区间为82.10%~83.60%，波动幅度1.5 pp。seed 42在第2轮达到82.10%之后持续下跌，连续3轮指标无提升，触发patience=3早停；seed 66、99的训练损失持续压低至0.015/0.005，但验证损失在8–10轮突破1.0，属于步长过大、快速拟合后发生过拟合的典型特征。
- 1e-5属于收敛偏慢的情形。seed 42首轮dev loss达到1.39（另外两组仅0.90 / 0.77）；10轮训练结束后，三组train loss仍维持在0.067–0.132区间（2e-5组为0.014–0.053），最低值0.067仅相当于2e-5组第6–7轮的水平，整体收敛进度滞后约3.5轮。该学习率不会出现训练发散，但在固定epoch限制下收敛不足，最终Acc虽然可以追平，Macro-F1仅为81.61。

结论：2e-5。它的首轮dev Acc（78.9%）与3e-5（79.3%）接近，末轮dev loss（0.949）低于3e-5（0.993），种子间标准差仅0.28，是三者里兼顾收敛速度与实验稳定性的最优取值。

图 6：同一组 run 的 Macro-F1 与三个 micro 指标。第 1 轮之后两条 Macro-F1 轨迹接近，末轮 bs=8 为 81.69%、bs=16 为 81.26%；在 seed 42 上 bs=8 的最优值（82.50）反而高于 bs=16（81.96）。组间差异只有在 3 种子均值上才显现（81.98 对 81.28），单条轨迹不足以支撑配置排序。

- bs=8 的验证集 Acc 峰值来自单轮随机波动：83.6% 的高点出现在第5轮，前后两轮指标分别为81.2%、81.9%，相邻两轮波动幅度达2.4 pp；该组逐轮抖动均值为1.38 pp，超过基线bs=16同种子（0.61 pp）的两倍（3种子均值0.99 vs 0.64）。若直接以单轮dev Acc挑选最优权重，很容易选中这一虚假峰值，和测试集上ΔAcc = −0.57 pp的性能落差对应。bs=8种子间极差可达1.69 pp（82.05%~83.74%），而bs=16的标准差仅0.28，稳定性显著更优。
- bs=8的验证损失谷底出现更早、回升斜率更陡峭：bs=8三组种子均在第2轮抵达loss最低点（bs=16在第3轮），之后以0.067/轮快速回升，是所有实验组里回升最剧烈的；末轮dev loss均值1.135，相比bs=16的0.949高出20%。从最低点到训练结束，bs=8损失平均回升61%，bs=16仅回升40%，对应图5上排右侧损失曲线在约1.1k步交叉后不再收拢，也就是bs=8第3轮末的位置。
- 更频繁的梯度更新没有学习到更优质的特征：末轮train loss三种子均值bs=8为0.024，bs=16为0.029，bs=8训练损失反而更低；但对应的验证损失bs=8高出0.19。训练损失更低、验证损失更高，说明额外的梯度更新大多在拟合小批次内部的样本噪声。每10步采样记录也可以佐证：bs=8在第4–7轮批内损失峰值达到1.07 / 1.36 / 0.92 / 0.96，而bs=16从第4轮开始批内损失峰值始终不超过0.46。

结论：bs=16。在8GB显存、3000条训练样本的条件下，减半batch size仅带来更频繁的梯度更新与更大的训练方差，没有提升模型精度上限。

## 6. 复现指南

### 6.1 环境

```bash
conda create -n dl python=3.10 -y
conda activate dl
pip install -r requirements.txt
```

|      依赖       |  版本  |
| --------------- | ------ |
| Python          | 3.10   |
| torch           | 2.5.1  |
| transformers    | 4.45.2 |
| tokenizers      | 0.20.3 |

| numpy           | 2.0.1  |

每次训练前调用 `utils.set_seed(seed)`：固定 `random`、`numpy`、`torch` 与 CUDA 的随机种子，并设 `cudnn.deterministic = True`、`cudnn.benchmark = False`。相同的软硬件环境下同一 seed 可复现；更换 GPU 型号或 cuDNN 版本后仍可能出现数值差异。

代码默认**离线加载** `bert-base-chinese`（`HF_HUB_OFFLINE=1`），运行前需确保模型已在本地 Hugging Face 缓存中：

```bash
python -c "from transformers import AutoTokenizer; AutoTokenizer.from_pretrained('bert-base-chinese')"
```

### 6.2 配置文件

`configs/params.json` 已固定为交付配置，无需改动：

```json
{
  "model_name": "bert-base-chinese",
  "max_length": 128,
  "batch_size": 16,
  "lr": 2e-5,
  "max_epochs": 10,
  "patience": 3,
  "seed_list": [42, 66, 99],
  "dropout": 0.1,
  "max_norm": 1.0,
  "warmup_ratio": 0.1
}
```

### 6.3 运行

```bash
python main.py
```

一次运行依次完成 `[42, 66, 99]` 三个种子的训练。每个种子：

1. 建 SwanLab run，命名 `seed{seed}_lr{lr}_bs{bs}_dp{dp}`；
2. 训练 + 每轮验证，按 dev Acc 保存 `outputs/best_bert_seed{seed}.pth`；
3. 加载最优权重评估测试集；
4. 全部结束后打印 `mean ± std` 汇总。

预期输出：

```
当前设备：cuda
训练集: 3000 条 | 验证集: 1000 条 | 测试集: 1064 条
全局汇总自动检测到 15 个类别。
...
Epoch 7 | Train Loss: 0.0490 | Dev Acc: 83.20% | Dev Macro-F1: 81.96% | Dev Micro-F1: 83.20%
seed42 表现更好，保存 checkpoint (Acc: 83.20%)
...
  全部种子实验最终汇总结果
平均 Test Acc:        83.08% ± 0.28%
平均 Test Macro-F1:   81.98% ± 0.15%
```

### 6.4 复现实验矩阵

改 `configs/params.json` 的对应字段即可，一次只改一项：

```bash
# G1: dropout
#   0.1 → 0.2（初始基线）→ 0.3 → 0.4，其余不动
# G2: 学习率
#   1e-5 / 2e-5 / 3e-5，bs=16, dp=0.1
# G3: batch size
#   8，lr=2e-5, dp=0.1
```

每组 3 个种子约需 8–12 min；21 次运行全量约 1 h。

### 6.5 已知问题
