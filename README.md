## 1. 项目概览

### 1.1 主要结果

| 项目                | 结果                                                                     |
| ----------------- | ---------------------------------------------------------------------- |
| 交付配置              | `lr = 2e-5` · `batch_size = 16` · `dropout = 0.1` · `max_length = 128` |
| **Test Accuracy** | **83.08% ± 0.28%**（3 seeds: 42 / 66 / 99）                              |
| **Test Macro-F1** | **81.98% ± 0.15%**                                                     |
| 训练成本              | 单 seed 约 2–4 min，全量约 1 h（RTX 3070 Ti Laptop, 8 GB）                     |
| 记录方式              | SwanLab 全程记录，`swanlog/` 下 21 个 run 可离线解析                               |

### 1.2 主要工作

- **单变量消融**：Dropout（0.1 / 0.2 / 0.3 / 0.4）→ 学习率（1e-5 / 2e-5 / 3e-5）→ Batch Size（8 / 16），每次只动一个参数，其余锁定。
- **多种子重复**：每组 3 个种子，报告 `mean ± std` 当两组指标差距很小、在种子随机波动范围内，认为性能近似等价。
- **数据审计**：训练前统计三份数据的重复标题、标签冲突与长尾分布，并估计其对指标的影响。
- **可复现**：固定数据文件、固定 seeds、`cudnn.deterministic=True`，超参写入 `configs/params.json`，单条命令完成 3 个种子的训练。

## 2. 数据集

### 2.1 基本情况

来源为今日头条文本分类数据集（TNEWS）切片。每行 5 个字段、以 `_!_` 分隔，第 2 字段为类别 `code`，第 4 字段为新闻标题。**模型只使用标题**，共 15 个类别（标签 `100–116`，实际缺少 `105`、`111`）。

| 划分  | 文件             |  样本数 |
| --- | -------------- | ---: |
| 训练集 | `train_3k.txt` | 3000 |
| 验证集 | `dev_1k.txt`   | 1000 |
| 测试集 | `test_1k.txt`  | 1064 |

### 2.2 数据审计

对三份数据做标题级比对：

| 检查项               | 数量 | 影响                          |
| ----------------- | -: | --------------------------- |
| train 与 test 重复标题 | 31 | 约 2.9% 的测试样本在训练中出现过，指标略微偏乐观 |
| train 与 dev 重复标题  | 28 | 早停与选 checkpoint 的验证信号略偏乐观   |
| dev 与 test 重复标题   | 18 | 选参与评估共享样本，削弱独立性             |
| train 内部重复标题      | 63 | 等效训练样本量低于 3000              |
| 同名不同标签（跨划分冲突）     |  3 | 标注噪声，模型无法全部判对               |

本实验未修改原始数据，上述重叠会使指标偏高。

## 3. 方法

### 3.1 模型

```python
# 1. BERT 主干提取 [CLS] 句向量特征
outputs = self.bert(input_ids=input_ids, attention_mask=attention_mask)
pooled = outputs.pooler_output   # 形状: [B, hidden_size]

# 2. 动态获取特征维度，过 Dropout 后进行分类映射
hidden_size = self.bert.config.hidden_size
logits = self.classifier(self.dropout(pooled))   # 形状: [B, num_labels]

# 3. 计算交叉熵损失
loss = self.loss_fct(logits.view(-1, self.num_labels), labels.view(-1))
```

- 取 **`pooler_output`**（`[CLS]` 经 `Linear + Tanh` 后的句子级向量），而非对所有 token 做 mean pooling。标题短、关键信息集中，`[CLS]` 在预训练阶段已被训练为聚合句义；实现上也不必处理 padding mask 的加权平均。
- 分类头只有一层线性层。3000 条样本难以支撑更深的头部，增加层数会加快过拟合。

### 3.2 训练配方

| 组件         | 设置                                 | 说明                                  |
| ---------- | ---------------------------------- | ----------------------------------- |
| 优化器        | AdamW（`weight_decay = 0`）          | 代码仅设置学习率，未启用权重衰减；本实验的正则项只来自 dropout |
| 学习率调度      | Linear warmup (10%) + linear decay | 前 188 步线性升温，避免初期大梯度破坏预训练权重          |
| 梯度裁剪       | `max_norm = 1.0`                   | 只缩放范数、不改变方向，抑制梯度爆炸                  |
| Batch size | 16                                 | 8 GB 显存上实测稳定；bs=32 未测（显存不足）         |
| 最大轮数       | 10                                 | 配合早停，21 次运行平均 8.2 轮（5–10 轮）         |
| 早停         | `patience = 3`                     | 监控 dev Acc，连续 3 轮未提升即停止             |
| 模型选择       | dev Acc 最高的 checkpoint             | 测试集不参与 run 内的 checkpoint 选择         |
| 随机种子       | 42 / 66 / 99                       | 覆盖 3 次独立初始化与数据打乱                    |

## 4. 实验设计

### 4.1 研究问题

| 编号  | 问题                        | 对应实验 |
| --- | ------------------------- | ---- |
| RQ1 | Dropout 如何影响过拟合边界与长尾类表现？  | G1   |
| RQ2 | 学习率如何影响收敛速度与训练稳定性？        | G2   |
| RQ3 | Batch size 如何影响梯度噪声与最终精度？ | G3   |

### 4.2 固定参数

```json
{
  "model_name": "bert-base-chinese",
  "max_length": 128,
  "max_epochs": 10,
  "patience": 3,
  "seed_list": [42, 66, 99],
  "max_norm": 1.0,
  "warmup_ratio": 0.1
}
```

### 4.3 实验矩阵：坐标下降而非全网格

| 组  | 维度         | 取值                | 锚点                |   runs |
| -- | ---------- | ----------------- | ----------------- | -----: |
| G0 | 初始基线       | `2e-5 / 16 / 0.2` | —                 |      3 |
| G1 | Dropout    | `0.1 / 0.3 / 0.4` | `2e-5 / 16 / 0.2` |      9 |
| G2 | 学习率        | `1e-5 / 3e-5`     | `2e-5 / 16 / 0.1` |      6 |
| G3 | Batch size | `8`               | `2e-5 / 16 / 0.1` |      3 |
|    |            |                   | **合计**            | **21** |

先固定 `lr=2e-5, bs=16` 扫 dropout（G1），确定 0.1 为最优后，再以 `2e-5 / 16 / 0.1` 为锚点扫学习率（G2）与 batch size（G3）。

两个未纳入的点：

- **`bs=32`**：未实测。按显存估算 OOM 风险较高（`max_length=128` 下 batch 翻倍、激活显存翻倍）；强行缩短序列又会引入「截断长度」这一额外变量。若需更大 batch，可用梯度累积（bs=16 × 累积 2 步）模拟。
- **`lr=4e-5`**：3e-5 已出现明显震荡，继续加大只会放大不稳定。

### 4.4 评估协议

| 阶段                     | 使用数据             | 决策依据            |
| ---------------------- | ---------------- | --------------- |
| run 内训练                | train            | —               |
| run 内早停 / 选 checkpoint | dev Acc          | 每个 run 独立保存最优权重 |
| 跨配置排序                  | test（3 seeds 均值） | 验收指标为 test Acc  |

每个 run 内部用 dev 做早停与模型选择，跨配置比较使用 3 个种子的 test 均值。dev 仅 1000 条，7 组配置的 dev 均值集中在 0.66 pp 的区间内，与种子噪声同量级，不足以区分组间差异。test 指标在训练结束后单独评估，由 `main.py` 汇总打印；SwanLab 只记录 dev 曲线与训练损失。

Micro 与 Macro 指标的互补性：
在单标签多分类下，Micro-P/R/F1 恒等于全局准确率（Accuracy），反映整体预测水平；而 Macro-F1 对各类别平权，能够精准暴露模型在长尾稀有类上的表现。实验表明，部分高 Micro 指标（Acc）的配置，其 Macro-F1 方差极大。因此，本实验以 Macro-F1 及标准差作为超参数优选的核心依据，以确保模型不仅整体准确，且对少数类也有稳定的判别力。

### 5.2 消融分析

三组消融按 dropout、学习率、batch size 的顺序展开，每组先给 3 种子均值，再配该组的曲线，最后给出结论。单条轨迹只用于展示形态，配置排序一律以 3 种子均值为准。

#### 5.2.1 Dropout

|   0.1   | 83.08 |   81.98  |   0.15   |     0.029     |    6.7   |
|   0.2   | 83.05 |   81.50  |   0.24   |     0.038     |    5.7   |
|   0.3   | 82.71 |   80.07  | **2.33** |     0.046     |    5.7   |
|   0.4   | 82.58 |   79.93  | **2.14** |     0.071     |    4.0   |

- **Acc 与 F1 的差异化表现**：`dropout=0.1` 与 `0.2` 的 Acc 仅相差 0.03 pp（约等于 0.3 条样本的误差），但在 Macro-F1 上，0.1 比 0.2 高出 0.48 pp，且方差缩小了 1.6 倍。随着 dropout 增大至 0.4，Acc 仅下降 0.50 pp，但 Macro-F1 暴跌了 2.05 pp。
- **强 Dropout 对长尾类的破坏**：`dropout=0.3` 时 F1 标准差剧增至 2.33，尤其是在 `seed=99` 的离群点上，Acc 维持在 82.50% 的正常水平，但 Macro-F1 崩盘至 76.54%。这说明强正则化并没有影响模型对多数大类的识别，而是直接摧毁了长尾稀有类的微弱特征。
- **过拟合与欠拟合的权衡**：`dropout=0.4` 的训练损失是 0.1 组的 2.4 倍，最优早停轮次提前，且验证集 Acc 并未提升。说明在小数据集上，过强的正则化只会导致长尾特征学习不足。

**结论**：`dropout=0.1`。在 Acc 等价的前提下，它提供了最高的 F1 得分与极小的方差，是小数据集微调的最佳平衡点。

- **收敛速度的差异**：学习率主要影响前期收敛快慢，对最终精度上限影响有限。`1e-5` 首轮 Dev Acc 仅 73.3%，虽然最终追平了 Acc，但整体收敛进度滞后约 3.5 轮，且 Macro-F1 略低（81.61）。

**结论**：`lr=2e-5`。它是兼顾快速收敛与稳定泛化的最优平衡点。

- **验证集指标的虚假峰值**：`bs=8` 的逐轮抖动均值高达 1.38 pp（基线 `bs=16` 仅 0.64 pp）。它在第 5 轮出现的 83.6% 峰值，属于典型的单轮随机波动，导致按验证集选出的最优权重在测试集上产生了 −0.57 pp 的性能落差。
- **过拟合出现更早、更剧烈**：`bs=8` 的验证损失谷底更早（第 2 轮），且回升斜率极陡。末轮验证损失为 1.135，比 `bs=16` 的 0.949 高出 20%，说明模型的泛化能力退化严重。
- **小批次梯度噪声的副作用**：虽然 `bs=8` 的末轮训练损失更低（0.024 vs 0.029），但验证损失却更高。这说明小批次多出来的更新次数，并未学到更优的语义特征，反而是在过度拟合小批次内部的样本噪声。

**结论**：`bs=16`。在 8GB 显存和 3000 条样本的约束下，减小 batch size 并不能提升模型精度上限，只会带来更大的训练方差和更早的过拟合。

## 6. 运行

```bash
pip install -r requirements.txt
python main.py
```

依赖版本见 `requirements.txt`；一次运行依次训练 `[42, 66, 99]` 三个种子，结束后打印 `mean ± std` 汇总。



交付配置：`lr = 2e-5`、`batch_size = 16`、`dropout = 0.1`、`max_length = 128`，完整参数见 `configs/params.json`：

```json
{
  "model_name": "bert-base-chinese",
  "max_length": 128,
  "batch_size": 16,
  "lr": 2e-5,
  "max_epochs": 10,
  "patience": 3,
  "seed_list": [42, 66, 99],
  "dropout": 0.1,
  "max_norm": 1.0,
  "warmup_ratio": 0.1
}
> **复现消融实验**：只需修改 `configs/params.json` 中的对应字段（如 `dropout` 改为 `0.2`，或 `lr` 改为 `1e-5`），再次运行 `python main.py` 即可。
>
> **产物保存**：每次运行会自动生成带时间戳的独立文件夹（`outputs/exp_YYYYMMDD_HHMMSS/`），模型权重与 SwanLab 本地日志均保存在内，互不覆盖。
